# 内核内存管理

## 用户空间 vs 内核空间内存

| 对比 | 用户空间 | 内核空间 |
|------|----------|----------|
| 分配函数 | `malloc()` / `calloc()` | `kmalloc()` / `kzalloc()` / `vmalloc()` |
| 释放函数 | `free()` | `kfree()` / `vfree()` |
| 地址范围 | 0 ~ TASK_SIZE | TASK_SIZE ~ 最大地址 |
| 访问保护 | 页表保护 | 可以访问所有物理内存 |
| 分配失败 | 返回 NULL | 返回 NULL（必须检查） |

> ⚠️ **内核中分配失败必须处理**，否则空指针解引用会导致内核 panic（系统崩溃）。

---

## kmalloc — 小块连续物理内存

```c
#include <linux/slab.h>

// 分配 size 字节的连续物理内存
void *kmalloc(size_t size, gfp_t flags);

// 分配并清零
void *kzalloc(size_t size, gfp_t flags);

// 释放
void kfree(const void *ptr);
```

### GFP 标志

`flags` 参数控制内存分配行为：

| 标志 | 含义 | 使用场景 |
|------|------|----------|
| `GFP_KERNEL` | 可睡眠、可等待 | 进程上下文（最常用） |
| `GFP_ATOMIC` | 不可睡眠、立即返回 | 中断处理、自旋锁持有期间 |
| `GFP_DMA` | 从 DMA 区域分配 | 需要 DMA 的设备 |
| `GFP_USER` | 分配给用户空间 | 用户页面 |
| `GFP_NOIO` | 不触发 IO | IO 子系统内部使用 |
| `GFP_NOWAIT` | 不等待、不 IO | 最严格的分配 |

```c
// 进程上下文中分配
char *buf = kmalloc(1024, GFP_KERNEL);
if (!buf) {
    pr_err("kmalloc failed\n");
    return -ENOMEM;
}

// 中断上下文中分配（不能睡眠）
char *buf = kmalloc(1024, GFP_ATOMIC);

// 分配并清零（推荐，避免未初始化数据问题）
char *buf = kzalloc(1024, GFP_KERNEL);

// 使用完后释放
kfree(buf);
```

### kmalloc 限制

- 分配大小通常最大 **128KB**（`KMALLOC_MAX_SIZE`）
- 分配的是**物理连续**内存
- 适合小块分配（几字节到几十 KB）

## vmalloc — 大块虚拟连续内存

```c
#include <linux/vmalloc.h>

void *vmalloc(unsigned long size);
void vfree(const void *ptr);
```

### kmalloc vs vmalloc

| 对比 | kmalloc | vmalloc |
|------|---------|---------|
| 物理连续 | ✅ 是 | ❌ 否（虚拟连续，物理可不连续） |
| 最大大小 | ~128KB | 可达几 GB |
| 分配速度 | 快 | 慢（需要建立页表） |
| 访问速度 | 快 | 慢（可能跨多个页面） |
| 适用场景 | DMA、硬件需要物理连续 | 大缓冲区、不需要物理连续 |

```c
// 分配大块内存
void *big_buf = vmalloc(1024 * 1024);  // 1MB
if (!big_buf) {
    pr_err("vmalloc failed\n");
    return -ENOMEM;
}

// 使用完后释放
vfree(big_buf);
```

## 内核栈上分配

```c
// 小数据可以直接用内核栈（内核栈通常只有 8KB 或 16KB）
char small_buf[64];

// ⚠️ 绝对不要在栈上分配大数组
// char huge_buf[4096];  // 危险！栈溢出 → 内核崩溃
```

## slab 分配器（高级）

内核频繁分配/释放同类型对象时，使用 slab 缓存可以提高效率：

```c
#include <linux/slab.h>

// 创建 slab 缓存
struct kmem_cache *my_cache;
my_cache = kmem_cache_create("my_cache",        // 名称
                              sizeof(struct my_obj),  // 对象大小
                              0,                    // 对齐
                              0, NULL);             // 标志, 构造函数

// 从缓存中分配对象
struct my_obj *obj = kmem_cache_alloc(my_cache, GFP_KERNEL);

// 归还对象到缓存
kmem_cache_free(my_cache, obj);

// 销毁缓存（模块卸载时）
kmem_cache_destroy(my_cache);
```

> slab 分配器维护一个**对象池**，分配/释放只是从池中取/还，避免频繁调用底层分配器。

## 内存分配决策树

```
需要分配内存？
├── 小于 128KB 且需要物理连续？
│   ├── 是 → kmalloc / kzalloc
│   └── 否 → 可以用 vmalloc
├── 大于 128KB？
│   └── vmalloc
├── 在中断上下文？
│   └── 用 GFP_ATOMIC
├── 频繁分配/释放同类型对象？
│   └── kmem_cache (slab)
└── 小数据（< 几百字节）？
    └── 栈上分配即可
```

## 常见内存错误

### 1. 内存泄漏

```c
// ❌ 忘记释放
void *buf = kmalloc(1024, GFP_KERNEL);
return 0;  // buf 泄漏了

// ✅ 确保释放路径
void *buf = kmalloc(1024, GFP_KERNEL);
if (!buf)
    return -ENOMEM;

if (error_condition) {
    kfree(buf);
    return -EINVAL;
}

// ... 使用 buf ...
kfree(buf);
```

### 2. Use-After-Free

```c
// ❌ 释放后继续使用
kfree(buf);
printk("%s\n", buf);  // 危险！use-after-free

// ✅ 释放后置空
kfree(buf);
buf = NULL;
```

### 3. Double-Free

```c
// ❌ 重复释放
kfree(buf);
kfree(buf);  // 危险！double-free → 内核崩溃

// ✅ 释放后置空
kfree(buf);
buf = NULL;
kfree(buf);  // kfree(NULL) 是安全的空操作
```

### 4. 未检查返回值

```c
// ❌ 不检查分配是否成功
char *buf = kmalloc(1024, GFP_KERNEL);
strcpy(buf, "hello");  // 如果 kmalloc 返回 NULL → 崩溃

// ✅ 必须检查
char *buf = kmalloc(1024, GFP_KERNEL);
if (!buf)
    return -ENOMEM;
```

## 快速对照表

| 需求 | 推荐函数 |
|------|----------|
| 小块连续内存 | `kmalloc()` / `kzalloc()` |
| 大块内存 | `vmalloc()` |
| 频繁分配同类对象 | `kmem_cache_create()` + `kmem_cache_alloc()` |
| 释放 kmalloc 内存 | `kfree()` |
| 释放 vmalloc 内存 | `vfree()` |
| 中断上下文分配 | `GFP_ATOMIC` |
| 进程上下文分配 | `GFP_KERNEL` |
| 内核栈上 | 直接声明变量（小数据） |
