# 符号导出与模块依赖

## 为什么需要符号导出

内核模块之间、模块与内核之间需要**共享函数和变量**。默认情况下，模块中的符号（函数、变量）只在模块内部可见。要让其他模块使用，必须**显式导出**。

---

## EXPORT_SYMBOL

### 导出符号

```c
// module_a.c — 导出模块
#include <linux/module.h>

int shared_value = 42;

int shared_function(int x)
{
    return x * 2;
}

// 导出符号，任何模块都可以使用
EXPORT_SYMBOL(shared_value);
EXPORT_SYMBOL(shared_function);

static int __init mod_a_init(void) { return 0; }
static void __exit mod_a_exit(void) {}

module_init(mod_a_init);
module_exit(mod_a_exit);
MODULE_LICENSE("GPL");
```

### 使用导出的符号

```c
// module_b.c — 使用模块
#include <linux/module.h>

// 声明外部符号（用 extern）
extern int shared_value;
extern int shared_function(int x);

static int __init mod_b_init(void)
{
    printk(KERN_INFO "value = %d, result = %d\n",
           shared_value, shared_function(10));
    return 0;
}

static void __exit mod_b_exit(void) {}

module_init(mod_b_init);
module_exit(mod_b_exit);
MODULE_LICENSE("GPL");
```

---

## EXPORT_SYMBOL vs EXPORT_SYMBOL_GPL

| 宏 | 含义 | 使用限制 |
|----|------|----------|
| `EXPORT_SYMBOL(sym)` | 导出给**所有模块**使用 | 无限制 |
| `EXPORT_SYMBOL_GPL(sym)` | 只导出给 **GPL 兼容模块**使用 | 使用者必须声明 `MODULE_LICENSE("GPL")` |

```c
EXPORT_SYMBOL(my_func);          // 任何模块都能用
EXPORT_SYMBOL_GPL(my_func);      // 只有 GPL 模块能用
```

> 大多数内核符号都是 `EXPORT_SYMBOL_GPL` 导出的。如果你的模块没有声明 GPL 许可证，将无法使用这些符号。

## 模块依赖关系

### 自动依赖

当模块 B 使用了模块 A 导出的符号时，存在**依赖关系**：

```
模块 A（提供符号）
    ↑
    | 依赖
模块 B（使用符号）
```

### 查看依赖

```bash
# 查看模块依赖
modinfo hello
# depends:          # 该模块依赖的其他模块

# 查看哪些模块依赖于某个模块
cat /proc/modules
# hello 16384 0 - Live 0xffffffffc0000000
# world 16384 1 hello, Live 0xffffffffc0001000
#                ^^^^^ 数字表示被几个模块引用
```

### 模块加载顺序

```
# 正确：先加载 A，再加载 B
sudo insmod module_a.ko
sudo insmod module_b.ko

# 错误：B 先加载会失败
sudo insmod module_b.ko
# insmod: ERROR: could not insert module_b: Unknown symbol in module
```

### modprobe vs insmod

| 命令 | 行为 | 处理依赖 |
|------|------|----------|
| `insmod` | 直接加载指定 .ko 文件 | ❌ 不处理，手动管理 |
| `modprobe` | 从 `/lib/modules/$(uname -r)/` 查找并加载 | ✅ 自动解析依赖链 |

```bash
# insmod 需要手动处理依赖
sudo insmod module_a.ko
sudo insmod module_b.ko

# modprobe 自动处理（需要先 depmod）
sudo depmod -a                # 生成依赖数据库
sudo modprobe module_b        # 自动加载 module_a → module_b
```

---

## depmod 命令

`depmod` 扫描 `/lib/modules/$(uname -r)/` 下的所有 `.ko` 文件，生成依赖数据库：

```bash
sudo depmod -a                        # 扫描并生成 modules.dep
cat /lib/modules/$(uname -r)/modules.dep  # 查看依赖关系
```

输出示例：
```
kernel/drivers/hello.ko:
kernel/drivers/world.ko: kernel/drivers/hello.ko
```

## 模块别名

```c
// 在模块代码中声明别名
MODULE_ALIAS("my-driver");
MODULE_ALIAS("char-major-10-200");
```

```bash
# 通过别名加载
sudo modprobe my-driver        # 等价于加载声明了此别名的模块
```

## 限制导出范围（高级）

如果只想让**特定模块**使用符号，可以用条件编译：

```c
#ifdef MY_MODULE_INTERNAL
// 内部使用，不导出
static int internal_func(void) { ... }
#endif

// 公开接口，导出
EXPORT_SYMBOL_GPL(public_func);
```

## 符号查看工具

```bash
# 查看模块导出的符号
nm module_a.ko | grep -i "T\|D"       # T=函数, D=数据
# T shared_function
# D shared_value

# 查看模块未解析的符号（需要其他模块提供）
nm module_b.ko | grep " U "           # U=undefined（未定义）

# 查看内核导出的所有符号
cat /proc/kallsyms | head -20
```

## 注意事项

| 要点 | 说明 |
|------|------|
| 许可证匹配 | 使用 `EXPORT_SYMBOL_GPL` 导出的符号，使用者必须是 GPL 模块 |
| 卸载顺序 | 先卸载依赖方（B），再卸载提供方（A），否则 rmmod 会拒绝 |
| 符号冲突 | 两个模块不能导出同名符号 |
| 版本兼容 | 内核模块符号有版本校验（`modversions`），版本不匹配会拒绝加载 |
