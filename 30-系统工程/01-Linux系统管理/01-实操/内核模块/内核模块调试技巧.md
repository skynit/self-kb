# 内核模块调试技巧

## 调试的挑战

内核模块运行在**内核空间**，一个错误可能导致：
- 内核 Oops（可恢复的错误）
- 内核 Panic（系统崩溃重启）
- 数据损坏
- 硬件状态异常

与用户空间不同，不能用 `gdb` 直接调试运行中的内核模块（但可以用 KGDB）。

---

## 最基本：printk 调试

```c
// 在关键位置添加调试输出
static int my_func(void)
{
    pr_info("my_func: entered\n");

    // ... 关键操作前 ...
    pr_info("my_func: before operation, value = %d\n", value);

    result = do_something(value);

    // ... 关键操作后 ...
    pr_info("my_func: after operation, result = %d\n", result);

    return result;
}
```

```bash
# 实时查看
dmesg -w | grep my_func
```

> 这是最原始但最可靠的方法。内核开发者也大量使用 printk。

## Oops 信息解读

内核出错时会打印 **Oops** 信息，这是最重要的调试线索：

```
BUG: unable to handle kernel NULL pointer dereference at 0000000000000000
PGD 0 P4D 0
Oops: 0000 [#1] SMP
CPU: 0 PID: 1234 Comm: insmod Tainted: G           O      5.4.0-42-generic
RIP: 0010:my_init+0x15/0x1000 [hello]
Code: ...
RSP: 0018:ffffc90000a43e08 EFLAGS: 00010246
RAX: 0000000000000000 RBX: 0000000000000000 ...
...
Call Trace:
 ? my_init+0x15/0x1000 [hello]
 ? do_one_initcall+0x50/0x1b0
 ...
```

### 关键字段解读

| 字段 | 含义 |
|------|------|
| `unable to handle kernel NULL pointer dereference` | **空指针解引用**（最常见的错误） |
| `RIP: 0010:my_init+0x15/0x1000 [hello]` | 出错的**指令地址**（在 `my_init` 函数中，偏移 0x15） |
| `CPU: 0` | 出错的 CPU 编号 |
| `PID: 1234 Comm: insmod` | 出错的进程（加载模块时） |
| `Tainted: G` | 内核被污染（`G` = 加载了非 GPL 模块） |
| `Call Trace` | **调用栈**（最下面的最先调用） |

### 用 addr2line 定位源码行

```bash
# 需要知道模块加载地址 + 偏移
# 从 Oops 中获取：my_init+0x15
# 从 /proc/modules 获取模块加载地址

# 使用 addr2line
addr2line -e hello.ko -f 0x15
# 输出：my_init
#       hello.c:25

# 或者用 objdump 反汇编
objdump -d hello.ko | grep -A5 "my_init>"
```

## 常见内核错误

### 1. NULL 指针解引用

```
BUG: unable to handle kernel NULL pointer dereference at 0000000000000000
```

**原因**：使用了未初始化或已释放的指针。

```c
// ❌ 错误
struct my_device *dev = NULL;
dev->data = 10;  // 崩溃

// ✅ 检查
if (dev == NULL) {
    pr_err("dev is NULL\n");
    return -EINVAL;
}
```

### 2. 内存越界

```
BUG: unable to handle kernel paging request at ffff8800deadbeef
```

**原因**：访问了不属于你的内存地址。

```c
// ❌ 数组越界
char buf[10];
buf[100] = 'x';  // 越界

// ✅ 边界检查
if (index >= sizeof(buf))
    return -EINVAL;
```

### 3. 栈溢出

```
BUG: stack guard page was hit at ...
```

**原因**：在内核栈上分配了过大的数组（内核栈只有 8KB~16KB）。

```c
// ❌ 内核栈上分配大数组
char huge[8192];  // 超过栈大小

// ✅ 用 kmalloc
char *huge = kmalloc(8192, GFP_KERNEL);
```

### 4. 睡眠在原子上下文中

```
BUG: scheduling while atomic: insmod/1234/0x00000002
```

**原因**：在中断处理函数或持有自旋锁时调用了可能睡眠的函数（如 `kmalloc(GFP_KERNEL)`）。

```c
// ❌ 中断上下文中用 GFP_KERNEL
irqreturn_t my_irq(int irq, void *data)
{
    char *buf = kmalloc(1024, GFP_KERNEL);  // 可能睡眠！
}

// ✅ 用 GFP_ATOMIC
irqreturn_t my_irq(int irq, void *data)
{
    char *buf = kmalloc(1024, GFP_ATOMIC);  // 不睡眠
}
```

## 调试工具

### strace（用户空间）

```bash
# 跟踪系统调用，查看用户程序如何与设备交互
strace cat /dev/mydevice
# 可以看到 open, read, write, close 等系统调用
```

### ftrace（内核函数跟踪）

```bash
# 追踪内核函数调用
echo function > /sys/kernel/debug/tracing/current_tracer
echo my_init > /sys/kernel/debug/tracing/set_ftrace_filter
echo 1 > /sys/kernel/debug/tracing/tracing_on

# 查看跟踪结果
cat /sys/kernel/debug/tracing/trace
```

### KGDB（内核 GDB）

需要两台机器（或虚拟机 + 串口），可以用 GDB 单步调试内核模块。

## 防御性编程

```c
static int __init my_init(void)
{
    int ret;
    struct my_device *dev;

    // 1. 检查所有分配
    dev = kzalloc(sizeof(*dev), GFP_KERNEL);
    if (!dev) {
        pr_err("failed to allocate device\n");
        return -ENOMEM;
    }

    // 2. 检查所有函数返回值
    ret = register_chrdev_region(devno, 1, "mydev");
    if (ret) {
        pr_err("failed to register chrdev: %d\n", ret);
        goto err_free_dev;
    }

    // 3. 使用 goto 清理（内核风格）
    ret = cdev_add(&dev->cdev, devno, 1);
    if (ret) {
        pr_err("failed to add cdev: %d\n", ret);
        goto err_unreg_chrdev;
    }

    return 0;

// 反向清理
err_unreg_chrdev:
    unregister_chrdev_region(devno, 1);
err_free_dev:
    kfree(dev);
    return ret;
}
```

> 内核代码的错误处理风格是 **goto 反向清理**，不是直接 return。这是内核社区的标准做法。

## 快速对照表

| 现象 | 可能原因 | 排查方法 |
|------|----------|----------|
| NULL pointer dereference | 未初始化/已释放指针 | 检查 Oops 中的 RIP 地址 |
| scheduling while atomic | 原子上下文中睡眠 | 检查 GFP 标志 |
| stack guard page hit | 栈上分配过大 | 改用 kmalloc |
| kernel paging request | 内存越界/野指针 | 检查数组边界 |
| tainted kernel | 非 GPL 模块/外部驱动 | 添加 `MODULE_LICENSE("GPL")` |
| Module not found | 未安装头文件 | `apt install linux-headers-$(uname -r)` |
| Unknown symbol | 符号依赖未满足 | 先加载依赖模块或用 `modprobe` |
