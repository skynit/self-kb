# 内核模块入门 — 最简单的 Linux 内核模块

## 一、什么是内核模块

内核模块（Kernel Module）是一种可以**在运行时动态加载到 Linux 内核中的代码**，无需重新编译整个内核或重启系统。

用途：
- 设备驱动程序
- 文件系统驱动
- 网络协议栈扩展
- 系统调用扩展

---

## 二、最简单的内核模块代码

```c
// hello.c
#include <linux/module.h>    // 内核模块必须包含的头文件
// #include <linux/init.h>   // linux/module.h 已经包含了，可省略

// 初始化函数：模块加载时调用
static int __init hello_init(void)
{
    printk(KERN_INFO "Hello Linux Module\n");
    return 0;  // 返回 0 表示成功
}

// 清除函数：模块移除时调用
static void __exit hello_exit(void)
{
    printk(KERN_INFO "Goodbye Linux Module\n");
}

// 指定初始化函数和清除函数
module_init(hello_init);
module_exit(hello_exit);

// 描述性信息（必须包含 LICENSE，否则编译/加载时会有警告）
MODULE_LICENSE("GPL");
MODULE_AUTHOR("Author Name");
MODULE_VERSION("1.0");
```

### 代码解析

| 要素 | 说明 |
|------|------|
| `#include <linux/module.h>` | 内核模块**必须包含**的头文件，已包含 `linux/init.h` |
| `__init` 标识 | 标记函数**只在初始化期间调用**一次，初始化完成后内核会回收该函数占用的内存 |
| `__exit` 标记 | 标记函数只在模块卸载时调用，如果内核编译为不可卸载，该函数会被丢弃 |
| `module_init()` | 宏，指定模块加载时执行的初始化函数 |
| `module_exit()` | 宏，指定模块卸载时执行的清除函数 |
| `MODULE_LICENSE("GPL")` | **必须声明**许可协议，否则会有内核污染（tainted）警告 |
| `printk()` | 内核空间的打印函数（类似用户空间的 `printf`） |

> ⚠️ `__init` 只能用于**只调用一次的函数**（初始化函数）。如果函数会被重复调用，千万不能用这个标识。

## 三、Makefile

```makefile
# Makefile
KERN_DIR = /lib/modules/$(shell uname -r)/build  # 内核源码树路径
PWD := $(shell pwd)                                # 当前工作目录

obj-m := hello.o                                   # 要生成的内核模块

all:
	make -C $(KERN_DIR) M=$(PWD) modules          # 编译命令

clean:
	make -C $(KERN_DIR) M=$(PWD) clean            # 清理中间文件
```

### Makefile 解析

| 变量/命令 | 说明 |
|-----------|------|
| `KERN_DIR` | 内核源码树路径，`/lib/modules/$(uname -r)/build` 是软链接 |
| `obj-m` | 表示编译为可加载模块（`obj-y` 表示编译进内核） |
| `make -C $(KERN_DIR) M=$(PWD) modules` | 进入内核源码树目录，然后回到当前目录编译模块 |

### 内核源码树路径

```bash
# 查看当前内核版本
uname -r
# 输出：5.4.0-42-generic

# 查看软链接指向
ls -la /lib/modules/$(uname -r)/build
# 输出：/usr/src/linux-headers-5.4.0-42-generic
```

`/lib/modules/$(uname -r)/build` 是一个**软链接**，指向 `/usr/src/linux-headers-xxx`，其中包含编译内核模块所需的头文件和配置。

## 四、安装内核头文件

编译内核模块前，必须安装对应版本的内核头文件：

```bash
# Ubuntu/Debian
sudo apt-get install linux-headers-$(uname -r) linux-headers-generic

# Arch Linux
sudo pacman -S linux-headers

# Fedora/RHEL
sudo dnf install kernel-devel-$(uname -r)
```

安装后会生成：
```
/usr/src/linux-headers-$(uname -r)/
├── include/          # 内核头文件
├── Makefile          # 内核构建系统
├── scripts/          # 构建脚本
└── ...
```

## 五、编译与加载

### 编译

```bash
make
```

编译过程：
1. 进入内核源码树目录
2. 使用内核构建系统编译
3. 先生成 `.o` 目标文件
4. 再转换为 `.ko` 内核模块文件

产物：`hello.ko`

### 加载模块

```bash
sudo insmod hello.ko       # 加载内核模块（需要管理员权限）
```

### 查看已加载模块

```bash
lsmod                      # 列出所有已加载模块
lsmod | grep hello         # 过滤查找

# 等价于查看 /proc/modules
cat /proc/modules | grep hello
```

### 查看内核日志

```bash
dmesg                      # 查看内核环形缓冲区日志
dmesg | tail -5            # 查看最后 5 条
```

加载模块后，`dmesg` 会显示 `Hello Linux Module`。

### 卸载模块

```bash
sudo rmmod hello           # 卸载内核模块（注意不带 .ko 后缀）
```

卸载后，`dmesg` 会显示 `Goodbye Linux Module`。

## 六、内核模块的三种查看方式

### 1. lsmod 命令

```bash
lsmod | grep hello
```

### 2. /proc/modules 文件

```bash
cat /proc/modules | grep hello
```

`lsmod` 命令底层就是读取这个文件。

### 3. /sys/module/ 文件系统

```bash
# 模块加载后，会在 /sys/module/ 下创建对应目录
ls /sys/module/hello/

# 模块卸载后，目录自动消失
```

`/sys/module/<模块名>/` 目录下包含该模块的各种信息（版本、作者、参数等）。

## 七、不声明 LICENSE 的后果

如果代码中没有 `MODULE_LICENSE("GPL")`：

```bash
make
# 警告：module has no license
sudo insmod hello.ko
# 警告：module taints kernel
```

内核会被标记为 **tainted（被污染）**，某些内核功能（如某些符号的使用）会受到限制。

## 八、完整操作流程

```bash
# 1. 安装内核头文件
sudo apt-get install linux-headers-$(uname -r)

# 2. 编写代码 hello.c 和 Makefile

# 3. 编译
make

# 4. 加载模块
sudo insmod hello.ko

# 5. 查看模块
lsmod | grep hello

# 6. 查看内核日志
dmesg | tail -3

# 7. 卸载模块
sudo rmmod hello

# 8. 再次查看日志（Goodbye 消息）
dmesg | tail -3

# 9. 清理编译产物
make clean
```

## 九、关键概念总结

| 概念 | 说明 |
|------|------|
| 内核模块（.ko） | 可在运行时动态加载/卸载的内核代码 |
| insmod | 加载内核模块命令 |
| rmmod | 卸载内核模块命令 |
| lsmod | 查看已加载模块列表 |
| dmesg | 查看内核日志（printk 输出） |
| /proc/modules | 已加载模块信息文件 |
| /sys/module/ | 模块信息 sysfs 目录 |
| __init | 初始化函数标识（只调用一次，完成后释放内存） |
| __exit | 清除函数标识（卸载时调用） |
| module_init() | 指定初始化函数的宏 |
| module_exit() | 指定清除函数的宏 |
| MODULE_LICENSE() | 声明许可协议（必须） |
| Makefile obj-m | 编译为可加载模块（obj-y 编译进内核） |
| /lib/modules/$(uname -r)/build | 内核源码树路径（软链接） |
