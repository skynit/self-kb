# 知识库分类规范

## 一、分类原则

1. **一个文件只有一个物理归属**，跨领域关系使用双链和标签表达。
2. **以内容性质为第一分类维度**：理论、工程实践、项目、原始资料分开。
3. **原始资料与消化笔记并存**：原转录留在 `90-原始资料/`，整理后的笔记放入对应知识域。
4. **项目资料按交付目标归类**，不因其使用的技术栈而拆散。
5. **历史会话汇总保留原文**，放入各领域的 `90-历史会话汇总/`，不与已有原子笔记混合。

## 二、顶层目录

| 目录          | 职责                              |
| ----------- | ------------------------------- |
| `00-知识库`    | 首页、规范、模板、全局索引与迁移记录              |
| `01-收件箱`    | 尚未判断归属的新内容                      |
| `10-计算机科学`  | 稳定理论、学术论文与基础模型                  |
| `20-软件开发`   | 编程语言、框架、数据库、测试、版本控制和开发工具        |
| `30-系统工程`   | Linux 实操、内核驱动、网络、存储、SMB、容器和桌面环境 |
| `40-AI与自动化` | LLM、AI 工具和自动化工作流                |
| `50-命理`     | 命理原文、概念、技法、学习笔记和专题研究            |
| `70-项目`     | 有明确交付物的工作资料                     |
| `80-日记`     | 按日期记录的日记                        |
| `90-原始资料`   | 剪藏、完整转录、外部仓库和未消化材料              |
| `99-归档`     | 已失效但仍需保留的内容                     |

## 三、判断流程

1. 这是原始转录或外部资料吗？是则进入 `90-原始资料`。
2. 这是某个产品或工程的专用决策吗？是则进入 `70-项目`。
3. 它主要解释稳定原理吗？是则进入 `10-计算机科学`。
4. 它是编程、框架或研发流程吗？是则进入 `20-软件开发`。
5. 它是系统运维、内核、网络或存储实操吗？是则进入 `30-系统工程`。
6. 无法立即判断时，先放入 `01-收件箱`，不新建含糊分类。

## 四、命名与链接

- 顶层领域使用两位数字前缀。
- 同一目录中文件名应能直接表达主题，避免 `note1`、`其他`之类名称。
- MOC 和全局索引使用完整路径双链；领域内唯一概念可使用短链接。
- 移动文件后必须检查双链、Markdown 相对链接和本地图片。
