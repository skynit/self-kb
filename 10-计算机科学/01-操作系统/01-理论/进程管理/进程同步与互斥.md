# 进程同步与互斥

## 基本概念

- **同步**：多个进程按**约定的顺序**执行（如生产者-消费者）
- **互斥**：同一时刻只允许一个进程访问**临界资源**

## 临界区问题

临界区（Critical Section）：访问临界资源的代码段。

### 进入区的三个条件

1. **空闲让进**：临界区空闲时，允许一个进程进入
2. **忙则等待**：已有进程在临界区时，其他进程必须等待
3. **有限等待**：等待进入的进程不会无限等待

## 实现互斥的方法

### 1. 软件方法

**Peterson 算法**（双进程）：

```c
// 进程 i
flag[i] = true;       // 我想进入
turn = j;             // 让对方先
while (flag[j] && turn == j);  // 等待
// 临界区
flag[i] = false;
```

### 2. 硬件方法

- **关中断**：简单但不适用于多处理器
- **TestAndSet（TSL）**：硬件原子指令
- **Swap 指令**：硬件原子交换

### 3. 信号量（Semaphore）

```
P(S):  S.value--;  if (S.value < 0) 阻塞当前进程
V(S):  S.value++;  if (S.value <= 0) 唤醒一个等待进程
```

**互斥信号量**（mutex）：初值 = 1
**同步信号量**：初值 = 0

### 4. 管程（Monitor）

- 高级同步原语
- 将共享数据和操作封装
- 同一时刻只有一个进程在管程内执行
- 条件变量（`wait` / `signal`）

## 经典同步问题

| 问题 | 核心要点 |
|------|----------|
| 生产者-消费者 | 互斥 + 两个同步信号量 |
| 读者-写者 | 读者共享，写者独占 |
| 哲学家就餐 | 死锁预防（限制同时就餐人数） |

## 经典考点

> - P、V 操作必须**成对出现**，且不能遗漏
> - 互斥信号量的 P 操作必须在同步信号量**之后**
> - 管程比信号量更安全（不会遗漏 V 操作）
