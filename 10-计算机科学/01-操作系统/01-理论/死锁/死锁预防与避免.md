# 死锁预防与避免

## 死锁预防（破坏必要条件）

### 破坏"请求与保持"

- 进程开始前**一次性申请所有资源**
- 缺点：资源利用率低，可能饥饿

### 破坏"不可剥夺"

- 请求不到新资源时，**释放已持有的资源**
- 适用于 CPU、内存等状态易保存的资源

### 破坏"循环等待"

- 所有资源**编号**，进程按编号递增顺序申请
- 实用且常用

## 死锁避免

### 安全状态

系统能找到一个**安全序列**（所有进程都能顺利完成）。

### 银行家算法

核心数据结构：

| 结构 | 含义 |
|------|------|
| `Available[m]` | 每类资源的可用数量 |
| `Max[n][m]` | 每个进程的最大需求 |
| `Allocation[n][m]` | 每个进程已持有的资源 |
| `Need[n][m]` | 每个进程还需要的资源（= Max - Allocation） |

**算法步骤**：

1. 进程 Pi 发出请求 `Request[i]`
2. 检查 `Request[i] <= Need[i]`（不超过最大需求）
3. 检查 `Request[i] <= Available`（系统有足够资源）
4. **试探性分配**：
   - `Available -= Request[i]`
   - `Allocation[i] += Request[i]`
   - `Need[i] -= Request[i]`
5. 执行**安全性检查**：
   - 找一个 `Finish[i]=false` 且 `Need[i] <= Work` 的进程
   - 执行完释放资源：`Work += Allocation[i]`
   - 重复直到所有 Finish=true → **安全**，否则**不安全**（回滚）

## 经典考点

> 银行家算法重点掌握手动模拟步骤：给定 Available、Max、Allocation，判断是否安全，以及某请求是否可分配。
