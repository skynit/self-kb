# 系统调用与用户态/内核态

## 两种处理器状态

| 状态 | 权限 | 可执行操作 |
|------|------|-----------|
| **用户态**（目态） | 受限 | 只能执行非特权指令，不能直接访问硬件 |
| **内核态**（管态） | 完整 | 可执行所有指令，访问所有资源 |

## 为什么需要区分？

保护操作系统内核不被用户程序随意修改，保证系统安全和稳定。

## 状态切换

```
用户程序 → 系统调用 / 中断 / 异常 → 内核态
内核态   → 中断返回指令            → 用户态
```

切换过程：
1. 用户程序发起**系统调用**（陷入指令/trap）
2. CPU 从用户态切换到内核态
3. 内核执行对应服务程序
4. 执行完毕，返回用户态

## 系统调用的分类

| 类型 | 功能 | 示例 |
|------|------|------|
| 进程控制 | 创建/终止/等待 | `fork()`, `exit()`, `wait()` |
| 文件管理 | 打开/读写/关闭 | `open()`, `read()`, `write()` |
| 设备管理 | 请求/释放/读写 | `ioctl()`, `read()`, `write()` |
| 信息维护 | 获取/设置时间 | `getpid()`, `time()` |
| 通信 | 创建连接/收发 | `pipe()`, `shmget()`, `mmap()` |

## 系统调用 vs 库函数

- **库函数**：在用户态执行，如 `printf()`、`malloc()`
- **系统调用**：需要切换到内核态，如 `write()`、`brk()`
- 库函数可能**封装**系统调用（如 `printf` 底层调用 `write`）
