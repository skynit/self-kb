# IO 模型

## IO 控制方式的演进

### 1. 程序直接控制方式（轮询）

```
CPU 发出 IO 命令 → 反复检查状态 → 数据就绪 → CPU 逐字传输
```

- CPU 全程参与，忙等（busy waiting）
- CPU 利用率极低

### 2. 中断驱动方式

```
CPU 发出 IO 命令 → 去做其他事 → IO 完成中断通知 → CPU 传输数据
```

- CPU 不再忙等
- 但数据传输仍需 CPU 逐字搬运

### 3. DMA 方式

```
CPU 发出 DMA 命令 → DMA 控制器接管数据传输 → 传输完成中断
```

- 以**块**为单位传输，CPU 仅在开始和结束时介入
- 详见 [[DMA与缓冲]]

### 4. 通道方式

- 通道是专用的 IO 处理器
- 可执行**通道程序**（通道指令序列）
- 一个通道可控制多个设备
- CPU 干预最少

## 五种 IO 模型（Unix/Linux）

| 模型 | 特点 |
|------|------|
| **阻塞 IO** | `read()` 阻塞直到数据就绪 |
| **非阻塞 IO** | 轮询，未就绪立即返回 `EAGAIN` |
| **IO 多路复用** | `select`/`poll`/`epoll` 同时监听多个 fd |
| **信号驱动 IO** | 内核就绪后发 `SIGIO` 信号 |
| **异步 IO（AIO）** | 内核完成全部工作后通知用户 |

> 前四种都是**同步 IO**（数据从内核到用户空间的拷贝仍需等待），只有 AIO 是真正的异步。

## IO 多路复用

| 方法 | 底层 | 时间复杂度 | 特点 |
|------|------|-----------|------|
| `select` | 数组 | O(n) | fd 数量限制（1024） |
| `poll` | 链表 | O(n) | 无 fd 数量限制 |
| `epoll` | 红黑树 | O(1) | 支持边缘触发，性能最好 |
