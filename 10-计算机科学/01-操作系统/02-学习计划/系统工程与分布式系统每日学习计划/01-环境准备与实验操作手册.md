## 只在当前课程安排的实验日查阅

当前只学一门课。本页不是从头执行的待办，其他课程的命令保持关闭；第一轮只执行总纲中与当前课程对应的 E1～E6。A 节用于判断环境；B/C 仅在确需 xv6 时查阅；D 是第二轮完整分布式作业的参考；F 是后续主动 VM/网络操作的边界。不要从头依次执行整本手册。

每个关键实验共 60 分钟，包含环境检查、操作和结论；工具问题最多占 15 分钟。无法继续时转本节列出的源码/案例阅读，记“阅读替代”，下一天继续同一门课程；跨课程切换仍须先结束当前课。

### E1：系统调用与管道（C1，第 1 周）

1. 在已有 Linux 环境中，用 strace 跟踪自己新建的简单管道，例如 printf 输出经过 wc 计数；跟踪子进程并只关注 process/desc 类调用。
2. 标出创建、exec、read/write、close 和 wait；实际 syscall 名称可能因系统和 shell 而不同。
3. 只保留能解释 FD 与进程边界的几行。已有 xv6/GDB 环境时可以改跟踪一次系统调用，二选一。
4. 环境受阻：读 user/sh.c、kernel/syscall.c，画出同一条路径，不要求完成 trace 或 util 作业。

### E2：内存映射（C1，第 2 周）

1. 用自己创建的小程序预留最多 32 MiB 匿名内存，分“预留后”和“逐页写入后”暂停；先预测两个阶段。
2. 只读该进程的 maps/smaps，比较虚拟大小、RSS 和映射类型，记清观测的是哪个进程。
3. 已有 pgtbl 环境且希望练 C 时，可改写最小 vmprint，解释一个中间页表和叶子映射；两条路径不都做。
4. 环境受阻：手算 Sv39 查表并读 walk。预留/触页现象只帮助理解按需分配，不构成完整 COW 验证。

### E3：同课 C/pthread 竞态（C1，第 3 周）

1. 只使用 6.S081 thread 作业自带的 notxv6/ph.c 示例，已有环境比较单线程与多线程的现象。
2. 指出两个线程访问同一共享结构的冲突；用锁保护最小不变量并仅验证当前题目。
3. 不熟编译或没有环境时，直接画错误交错与正确锁保护的时序，记阅读替代。
4. 不另外安排 Go 并发教程、Go 工具链安装或框架练习。60 分钟包含所有步骤，到时停止。

### E4：本地请求观测（C2，第 8 周）

1. 使用已有工具在 loopback 启动自己的最小服务，确认进程和监听端口。
2. 发送一次请求，结合 ss、客户端结果和自己的流量抓包，识别监听、连接、数据与关闭。
3. 不抓业务流量；权限或工具受阻时读课程已有 pcap，注明数据来源；若没有 pcap，改画请求经过的各层。
4. 不为实验修改防火墙或真实网络；抓到传输数据不等于证明服务端业务已提交。

### E5：事务回滚与重启（C5，第 18 周）

1. 新建不含业务数据的临时 SQLite 数据库并建立一条基线数据，记录 journal_mode 与 synchronous。
2. 开启事务、修改数据而不 COMMIT，结束自己创建的客户端；重新打开数据库，检查未提交修改是否可见。
3. 另做一次修改并 COMMIT，正常关闭后重开查询，比较结果。
4. 只把结果称为进程中断与重开观察；它不验证掉电、磁盘缓存或所有文件系统组合。缺少 SQLite 时推演当前数据库课程的日志提交与恢复，不回头开启 OS 课程。

### E6：丢响应与重试（C6，第 19 周）

1. 在独立小程序里模拟服务端计数更新成功，但首次调用向客户端返回“回复丢失”。
2. 用相同操作再次调用，对比直接重复执行与按请求 ID 返回已有结果。
3. 用固定输入打印两段历史，标出发送、更新、丢回复和重试；用进程内调用即可，不搭集群。
4. 说明这个示例的去重状态只在内存中，未覆盖真实网络和重启；它也不替换 2026 KV 作业规定的 version/ErrMaybe 协议。

### C4. 每个作业独立 worktree，避免混用改动

```bash

```

其他题目的固定映射：

| 作业 | 远端分支 | 目录后缀 |
|---|---|---|
| 页表 | origin/pgtbl | xv6-pgtbl |
| 陷阱 | origin/traps | xv6-traps |
| 按需分配 | origin/lazy | xv6-lazy |
| COW | origin/cow | xv6-cow |
| 线程 | origin/thread | xv6-thread |
| 锁 | origin/lock | xv6-lock |
| 文件系统 | origin/fs | xv6-fs |

重复执行 worktree add 失败时先列现有 worktree 与分支，不删目录、不强制覆盖。若题目明确要求移植前题内容，只移植要求的部分，并说明依赖；不要整包复制旧实现。COW 和 lazy 的概念有关，不意味着课程两个分支默认共享你的实现。

## E. 工作目录只读阅读法

每次选一个入口，不递归扫描整个 rootfs、固件库或生成目录。

1. 先读该仓库 AGENTS.md 与局部说明。
2. 用 rg --files 或 git ls-files 找源码范围，排除 out-*、rootfs、cache、生成物。
3. 找入口函数，逐层跟三到五个调用，写出输入、输出、副作用、失败、资源所有者。
4. 遇到跨平台实现，看 Linux 对应文件；不要把其他平台代码当当前行为。
5. 查现有相关测试以了解契约，不自动执行硬件测试。
6. 提问分三栏：看到的事实、自己的推断、还缺的证据。
7. 没有新授权，不修改代码；不要把学习卡里假设的错误变成“顺手修复”。

例子，在安装器根目录只列受 Git 管理的 Go 文件：

```bash
rg -n '^func ' /home/skynit/workspace/cw/pkg/taskmanage/task_manager.go
```

若用户以后明确要求改工作代码，届时重新确认范围；仅测试当前修改或直接受影响包，不执行 go test ./...，不打开硬件/外部/破坏性测试开关。

## F. 虚拟机、磁盘与网络实验清单

### 启动任何安装操作之前

- [ ] VM 是专用学习实例，里面没有唯一业务数据。
- [ ] 虚拟盘是新建可丢弃文件，不是物理设备直通。
- [ ] 禁止把宿主 /dev 或工作根目录作为可写直通。
- [ ] 已记录虚拟盘的名字、容量和连接关系，能在安装界面对应起来。
- [ ] 有 VM 快照或已知可重新创建的基线。
- [ ] 默认断网或仅 NAT；不桥接业务网络、不在业务网络发送 DHCP。
- [ ] 不挂接真实 NAS 数据盘、不使用真实登录口令作为练习口令。
- [ ] 停止测试不会影响当前网络或远程会话。

如果任何项不能确认，停止主动实验，先做代码阅读与纸面推演。本文不提供对真实设备的 mkfs、wipefs、zpool destroy、BIOS 写入等命令。

### 网络和驱动

- 抓包默认读取课程生成的 packets.pcap；主动抓包只针对自己的练习接口和流量。
- 终止进程只针对自己刚创建并确认的 PID，不按模糊进程名批量清理。
- 不执行 driver 工具包的 install/uninstall/start/stop 来学习脚本；先只读。
- 真实 AP 会影响无线环境，DHCP/NAT 会影响网络；有专项授权和隔离条件才执行。
- 不设置不合法信道、不绕过监管域、不伪造固件版本或关闭 Secure Boot 来凑结果。
- 检查日志时不公开 Wi-Fi 口令、MAC、私网结构、密钥或认证头。

## G. 卡住时的 30 分钟定位法

1. 前 5 分钟：记录当前命令、目录、版本、第一条错误和预期结果。
2. 接着 5 分钟：分类为环境、编译、运行、协议、测试假设、性能之一。
3. 接着 10 分钟：缩小到一个文件/一个状态转移/一个测试；读错误现场，不一次改五处。
4. 最后 10 分钟：提出一个可证伪假设，只做一个验证；失败也保留证据。
5. 仍不清楚：当天停止堆功能，写“已排除什么、下一步查什么”，移入后续专项；第一轮下一天继续阅读主线。

常见区别：

- QEMU/编译器不识别参数：先查环境，不猜算法 bug。
- 没有匹配测试：过滤条件问题，不是通过。
- 竞争测试速度不足：先确认正确性、运行环境和负载，再看性能。
- 测试超时：可能死锁/丢唤醒/消息不收敛，也可能环境慢，不能直接调大超时。
- 输出与预期不同：先检查版本和输入，不删除测试断言。

## H. 如何请求帮助而保留学习收益

可以把下面的信息发给协作者：

“我在第 N 周 Day N，目标是……。版本/分支是……，当前运行目录是……。预期……，实际……。最小命令……，关键日志……。我已检查 A/B，假设 C。请先指出推理漏洞或下一条诊断，不直接给完整答案。”

遇到概念不懂可要求反例、执行追踪、检查设计；实现后可以要求审核边界。第一轮可以直接请求源码导读或反例，无需为证明尝试过而长时间调试。把帮助后的结论用自己的话复述，标注哪些由自己验证。
