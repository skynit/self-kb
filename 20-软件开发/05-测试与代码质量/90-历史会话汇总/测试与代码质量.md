# 测试与代码质量

> 来源：OpenCode 历史会话 | ~8 条

## Go 测试规范

- 测试文件与被测源文件同目录
- `_test.go` 后缀
- 使用 `go test` 运行
- 表驱动测试（table-driven tests）

## 常见测试任务

- **更新测试预期**：代码逻辑变更后同步更新期望值
- **清理未导出符号引用**：测试中引用私有函数需调整
- **废弃测试模式**：移除过时的 test pattern
- **批量修复 import 路径**：项目重构后更新

## 未引用导出符号（Dead Code）

查找项目中未被引用的导出函数/类型：
- 使用 `staticcheck` 或 `golangci-lint`
- 确认后删除或添加测试覆盖

## Postman 文件识别

`cw-smb-api.json` 符合 Postman Collection v2.x schema：
```json
{
  "info": {
    "_postman_id": "...",
    "name": "...",
    "schema": "https://schema.getpostman.com/json/collection/v2.1.0/collection.json"
  },
  "item": [...]
}
```

## 测试文件位置

- Go：`foo_test.go` 与 `foo.go` 同目录
- 也可在独立的 `test/` 目录中放置集成测试
- 探索项目中所有测试文件：`find . -name "*_test.go"`
