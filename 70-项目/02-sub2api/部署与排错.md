### 1. 代理配置 — 核心问题

sub2api **不使用** `HTTP_PROXY`/`HTTPS_PROXY` 环境变量做 API 转发。它有自己的代理管理系统：

- 在后台「IP 管理/代理管理」添加代理（HTTP, `172.19.0.2:7890`）
- 创建账号时绑定代理
- 或用数据库直接插：`proxies` 表 + `accounts.proxy_id`

### 2. Docker 网络

sub2api 和 clash 在不同网络时需要手动连接：

```
docker network connect clash_default sub2api
```

### 3. Codex 无法使用

**OpenAI 策略限制**，ChatGPT Plus OAuth 账号不允许通过 API 调用 Codex 模型。普通模型（gpt-5.5 等）完全正常。

### 4. CCSwitch URL

需要带 `/v1/` 前缀：

```
http://192.168.100.66:8080/v1/responses   ✅
http://192.168.100.66:8080/responses       ❌
```

### 部署清单

|步骤|说明|
|---|---|
|docker-compose up|启动 sub2api + postgres + redis|
|连接网络|`docker network connect clash_default sub2api`|
|添加代理|后台 → IP管理 → 添加 `172.19.0.2:7890` HTTP|
|添加账号|OAuth → refresh_token → 选代理|
|创建分组|把账号加入分组|
|创建 Key|生成 API Key 绑定分组|

已总结在上面了。另外这篇经验可以写进你的 `AGENTS.md` 或项目文档里，以后再部署就不用踩坑了。
