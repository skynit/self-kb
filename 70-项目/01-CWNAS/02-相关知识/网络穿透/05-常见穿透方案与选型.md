# 常见穿透方案与选型

返回 [[70-项目/01-CWNAS/02-相关知识/网络穿透/00-网络穿透知识导航|知识导航]]。

下表是按访问模型整理的比较。工具能力以 **2026-10-21 查阅的官方文档** 为依据；这里不指定“最新版本”，也不涉及价格或商业套餐承诺。选型建议是基于这些机制对 NAS 使用场景的工程判断。

## 1. 先区分三种访问目标

- **把一个网页交给浏览器访问**：用户希望输入域名即可进入 NAS 页面，重点是 HTTPS、身份认证和 Web 应用兼容。
- **让特定客户端访问某项服务**：可以要求安装桌面端或手机端，允许客户端承担身份和隧道逻辑。
- **像在家中一样访问整个网络**：除 NAS 网页外，还需要文件协议、SSH 或其他内网设备，更适合讨论虚拟组网与路由权限。

**HTTPS** 是使用 TLS 保护的 HTTP，通常由浏览器和 Web 服务/代理完成安全协商；**TLS** 是提供传输加密与对端认证的安全协议。它和“浏览器能否执行任意 UDP/TCP 穿透”是不同能力。后文所说“直接用浏览器”，指标准浏览器访问模式，不预装专门的网络客户端。

**SSH（安全外壳协议）** 通常由运维客户端连接 NAS 上的 SSH 服务，用来安全登录和执行命令；它与提供网页的 HTTP 服务不同。**虚拟组网** 则由专门客户端和网关建立逻辑网络及路由，使多种应用可以通过该网络寻址，不要求把每个应用改写成浏览器数据通道。

## 2. 总体比较

| 方案 | 谁运行什么 | 浏览器使用方式 | 数据路径 | 主要取舍 |
| --- | --- | --- | --- | --- |
| 公网 IPv4/IPv6 加访问规则 | 管理员配置地址、网关和 NAS 服务 | 可直接访问已发布的 HTTPS 服务 | 访问端到 NAS | 需真实公网可达性；服务入口和权限由自己维护 |
| frp 公网代理 | 公网机运行 `frps`，NAS 侧运行 `frpc` | 已发布 HTTP/HTTPS 服务可供浏览器访问 | 通常经 `frps` 转发 | 模型清楚；公网服务器带宽与入口管理成为重点 |
| frp STCP | 服务侧 `frpc` 与访问侧 visitor 配合 | 浏览器可连接访问侧提供的本地入口 | 经 frp 服务端转发 | 访问方需要运行 visitor，不是公开网页入口 |
| frp XTCP | 双方客户端配合，服务端协调 | 访问端需额外客户端/visitor | 尝试点对点传输 | 受 NAT/防火墙条件影响，应准备替代路径 |
| WebRTC DataChannel | 浏览器或原生客户端、NAS、信令及可选 TURN | 网页代码可使用 DataChannel | ICE 直连或 TURN 中继 | 需实现应用消息、身份和文件恢复等能力 |
| WireGuard | 两端或网关配置 WireGuard | 浏览器通过已建立的虚拟网络访问 | 加密 IP 隧道 | 核心提供安全组网；发现、协调和中继需另行设计 |
| Tailscale | 设备安装客户端，系统协调身份及连接 | 浏览器通过设备已加入的网络访问 | 直接连接，或 Peer Relay/DERP 等路径 | 省去部分协调工作；需理解控制系统与权限策略 |
| Cloudflare Tunnel | NAS/网关侧运行 `cloudflared`，连接 Cloudflare | 发布的 HTTP 应用可直接通过浏览器访问 | 经 Cloudflare 和隧道连接 | 依赖该入口体系；非 HTTP 访问有额外客户端或组网条件 |

工具角色和限制分别见 frp、WireGuard、Tailscale、Cloudflare 官方文档；WebRTC 的通道能力见 RFC 8831。[^S15][^S21][^S22][^S23][^S24][^S25][^S26][^S27][^S28]

## 3. frp：反向隧道、私有代理与点对点模式

**frp** 是一个反向代理工具，由项目维护方提供软件，部署者配置服务端和客户端。`frps` 是通常运行于公网服务器的服务进程；`frpc` 是运行于 NAS 或访问端的客户端进程。**反向隧道** 指内网端主动建立到公网端的连接，使公网端能经该通道把访问送回内网服务。[^S21]

普通公网代理可概括为：

```text
浏览器 → 公网域名/入口 → frps → frpc → NAS 本地服务
                                ↑
                    NAS 主动建立所需连接
```

这张图描述逻辑关系，不表示全部访问永远复用一条物理 TCP 连接。底层传输、连接复用及工作连接行为需要结合配置确认。[^S21]

**STCP** 是 frp 的一种私有 TCP 代理类型，通常由服务提供方配置代理，访问方配置 **visitor（访问者客户端）**，再连接 visitor 暴露的本地端口；它仍通过服务端承接转发。SUDP 是相应的私有 UDP 代理类型。[^S22]

**XTCP** 是 frp 用于点对点打洞的代理类型，双方客户端在协调后尝试直连。即使业务是 TCP 服务，也要区分业务侧与跨公网底层的协议。官方明确说明此类点对点方案不能适用于全部 NAT 环境，因此应按实际工具版本配置回退或提供另一路径。[^S23]

**工程判断：** 如果目标是尽快发布可控的 NAS Web 入口，反向代理通常比自定义一套文件传输协议更直接。如果目标是减少大文件中继成本，可以进一步评估点对点机制，但需要把客户端安装、成功率和回退体验一起纳入验收。

## 4. WireGuard 与 Tailscale 为什么不是同一个层次

**WireGuard** 提供基于密钥的加密网络隧道，由操作系统或相关实现创建虚拟网络接口。管理员配置 peer、公钥、端点和允许路由；**peer** 是可进行隧道通信的对端配置，区别于 WebRTC 的 PeerConnection。WireGuard 核心不替应用完成通用账号登录、设备发现、信令和 TURN 式中继服务。[^S24]

**Tailscale** 是在 WireGuard 等能力基础上提供设备身份、协调和组网体验的系统。连接可能直接建立，也可能使用 **Peer Relay** 或 **DERP**：Peer Relay 是配置为中继的设备参与转发；DERP 是其专用中继体系。连接的数据仍受 WireGuard 端到端加密保护。这里的 DERP 不是 TURN 服务器，也不是所有穿透工具通用的中继协议。[^S25][^S26]

**工程判断：** 团队自用、运维入口和完整内网访问适合优先评估虚拟组网。面向普通用户分享单个文件时，要求访问者先加入整个虚拟网络可能增加使用步骤，还需控制允许访问的设备与网段。

## 5. Cloudflare Tunnel 的能力边界

**Cloudflare Tunnel** 由内网侧 `cloudflared` 主动建立到 Cloudflare 的出站连接，使访问经 Cloudflare 到达已配置的源服务。**源服务** 是最终处理请求的 NAS 网页或其他本地服务，由部署者配置；它与面向用户的公网入口不是同一个地址角色。[^S27]

HTTP 应用可以按发布方式供浏览器访问。非 HTTP 协议并不因此都变成“任意客户端直接连接公网端口”：官方说明部分 TCP、SSH 等访问方式需要访问端运行 `cloudflared`，或采用客户端到隧道、私有网络等对应方式。实际行为要按具体协议阅读官方限制。[^S28]

**工程判断：** 它适合纳入 Web 入口的候选方案；如果产品需要任意原生文件协议、端到端 NAS 身份或特别的大流量传输，应进一步核对访问模型、数据路径和服务约束。

## 6. 面向 CWNAS 的选择顺序

以下为设计建议，不表示项目已经采用。

| 需求 | 优先评估 | 验收重点 |
| --- | --- | --- |
| 浏览器进入管理页面 | 公网 HTTPS、反向代理或受控 Web 隧道 | WebSocket、上传下载、会话安全、反向代理兼容 |
| 浏览器大文件传输 | WebRTC DataChannel 加可用 TURN 回退 | 直连比例、首连时间、中继带宽、分块与恢复 |
| 自有桌面端/手机端 | 应用集成的直连/中继或虚拟组网 | 网络切换、电量、后台限制、设备身份 |
| 自用 SSH 与多服务访问 | WireGuard/Tailscale 等组网 | 路由范围、最小权限、撤销与失联处理 |
| 发布单个 TCP 服务 | 公网映射或 frp 类反向隧道 | 入口鉴权、服务协议、限流、连接回收 |

评价方案时分别量化连接成功率、建立耗时、持续吞吐、运营成本和访问步骤；“直连成功率高”不自动意味着浏览器兼容性或业务恢复更好。

## 7. 一个中继带宽估算例子

假设文件大小为 **1 GiB**，其中 `GiB` 表示 `2^30` 字节，文件从 NAS 经一台中继到访问端：

```text
NAS → 中继：中继收到约 1 GiB 业务负载
中继 → 访问端：中继发出约 1 GiB 业务负载

中继的收发字节合计约 2 GiB
```

这是只计算业务负载的假设模型。协议封装、重传、双中继和其他请求会增加字节；云平台可能只按某个方向计费，不能把“网卡收发之和”直接当作账单。

若 20 个中继下载各以 `10 Mbit/s` 持续进行，则每个方向约需要 `200 Mbit/s` 的相应承载能力。直连比例可以降低中继负载，但容量规划还应覆盖直连大量失败、需要集中回退的情形。
